# ViteApp trading-rule parity audit

Bookmap must not introduce trading restrictions absent from ViteApp. Changes remain local.

## Extra restrictions removed

- Common-entry finite-time / after-open / before-16:00 gate. ViteApp only has a before-open gate in its B/S keyboard path, not its common entry checker.
- Common-entry size multiplier capped at 1. ViteApp rejects zero liquidity and applies its sizing multiplier without this cap.
- Common-entry extra validity gates for PnL/loss-limit positivity, open/VWAP/ATR, watch levels, no-trade-zone boundaries, and nonnegative finite volume. Mirror the actual ViteApp daily-loss predicate and price/volume comparisons instead.
- Experimental initial-entry flat-position/no-pending-orders requirement and its broker preflight (position read, pending-order read, and 3000-order truncation gate). Existing-position workflows already mirror ViteApp and must remain available.
- Requiring positive ordered day levels for every entry even when explicit entry and stop prices suffice.
- Locally rejecting entry/reload/pending-refresh stops on the other side of the entry, including a quote crossing the stop. ViteApp computes absolute price risk and leaves the order decision to the broker.
- Locally rejecting reset-profit targets that cross the protective stop. ViteApp's reset workflow does not impose that comparison.

## Checked rules with ViteApp counterparts

Attendance, watchlist limits, daily loss, zero liquidity, existing-position risk sizing, partial daily-loss/position-risk budgets, the half-daily-range add restriction, stop-tightening discipline, entry-area boundaries, retest blocking, split-partial requirements, and core-target exit protection remain. Sources: ViteApp controllers/entryRulesChecker.ts, algorithms/riskManager.ts, algorithms/rules.ts, controllers/handler.ts, controllers/coreTargetExitRules.ts, trading/core/controllers/coreTargetRule.ts, tradebooks/bookmapWallReversal.ts, and bookmap/bookmapSocket.ts.

Buying-power half sizing/warnings and profit-reset coverage validation exist in both apps' trading core. No extra insufficient-buying-power veto remains.

Native transport/data-contract checks (supported actions, required state, real price units, valid payload numbers, order direction/closing quantity, duplicate broker mutations, and ambiguous broker outcome review) remain. These are execution integrity checks rather than additional strategy/session policy. This audit does not assert that every native adapter check is byte-for-byte identical to browser code.

Regression fixtures are generated by ViteApp/scripts/generateDirectEntryFixtures.mjs using production TypeScript target/order helpers. They include session boundaries, a multiplier above 1, manual prices without day levels, and stop-side behavior. Native fake-broker tests verify no initial-entry preflight reads occur.
